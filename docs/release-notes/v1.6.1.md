## mind v1.6.1

Patch release focused on the OpenCode automation plugin: full OpenCode V2
support while keeping V1 compatibility, correct project-space resolution,
quieter and bounded plugin state, and accurate session identities on both
runtimes.

### Highlights

- **OpenCode V2 support** — the generated `~/.config/opencode/plugins/mind-automation.js`
  now default-exports a V2 plugin definition (`id` + `setup`) with native
  `context`/`compaction` session hooks and `ctx.event.subscribe`, while keeping
  the V1 `server()` hooks and the named export. V2 no longer rejects the plugin
  with `Plugin must export a default definition…`, and existing V1 installs keep
  working (verified on V1 1.18.28/1.18.33 and V2 2.0.19).
- **One project space per canonical project** — continuity artifacts are stored
  under `projects/<canonical-project>` even when events come from a nested or
  different directory.
- **Quieter, bounded plugin state** — state is written only after
  state-changing events, and the checkpoint/summary/handled maps are capped to
  the newest 400 entries.
- **Accurate session identities** — the plugin resolves the real session id on
  V2 stream events (`data.sessionID`) and V1 bus events
  (`properties.sessionID` / `properties.info.id`) instead of the event id, so
  dedupe keys and session summary names are correct on both.

### Fixed

- OpenCode automation plugin now loads on OpenCode V2: default export with
  `id` + `setup`, native V2 session hooks, and `ctx.event.subscribe`, keeping
  V1 `server()` hooks for compatibility.
- V2 automation resolves one project space per canonical project path
  (`location.project.canonical` takes precedence over the event directory).
- V2 automation writes plugin state only on state-changing events; state maps
  are capped to the newest 400 entries; empty or non-string session id fields
  no longer mask later fallbacks.
- V1 automation now uses the session id from event `properties`
  (`properties.sessionID`, `properties.session.id`, `properties.info.id`)
  instead of the bus event id, so checkpoint dedupe keys and session summary
  names use the real session.

### Upgrade notes

```bash
mind update
```

`mind update` refreshes detected agent integrations automatically, including
regenerating `~/.config/opencode/plugins/mind-automation.js`. No manual
`mind setup refresh` is required. Use `--no-refresh-integrations` if you need
to defer the refresh.

> **Restart your agentic host after updating** — fully quit and relaunch
> OpenCode (and any other agent host) so the refreshed plugin file and the
> updated `mind mcp` stdio process are re-read from disk. Running hosts keep
> the previous plugin and protocol cached until restarted.
